# 为中断恢复保留不可变清单

Issue #14 在 QV-1 SRS-11/D-04 的不可变分块、最后发布清单协议内，增加 `experiments/<id>/confirmed/manifest-<revision>.json`；封存另写 `manifest-<revision>-sealed.json`。每份清单引用当时完整前缀，文件关闭并读回成功后才成为恢复依据；`manifest.json` 继续提供旧读者的便利入口。同一实验的已发布清单与数据均不覆盖。原仓库没有 docs/adr；本编号独立于 docs/origin 的历史访谈编号及 Issue 中引用的历史决策。

单个覆盖清单在更新失败时可能丢失此前确认记录的入口。采用完整不可变清单保留旧入口，代价是清单历史的累计大小随批次数呈二次增长；本轮仍使用现有实验时长及样本预算，不承诺无限记录或全产品容量预算。压缩或增量清单须另行设计兼容性。封存前核验全部历史，日常提交逐文件关闭并读回新内容，避免每批反复读回全部历史。

恢复按修订降序核验权威清单及全部引用，损坏候选保留诊断，再寻找可核验前缀；旧记录没有 confirmed 目录时仍可核验 manifest.json。未引用文件只标记待排查，不自动采纳或删除。已关闭且可核验的新清单可能在页面收到提交确认前已发布，恢复时可以发现这个前缀；这不代表页面此前已确认它，也不推测崩溃终点。恢复返回只读数据，不返回原实验运行器。

真实 Chrome 进程强退与断电、内核崩溃不同；前者通过不构成硬件耐久承诺。断电耐久及完整产品多文件协议仍未验证，正式验收资格继续阻塞，内存独立研究仍可使用。若本轮浏览器强退用例失败，保留失败目录及记录，阻断依赖该故障保全能力的验收，不通过采样降级或隐式存储切换掩盖。
