## 修复及红绿证据

1. 首次步内触边：新增公开会话回归，旧实现返回running而测试要求stopped。修复后，两种峰值位置、左右方向、1ms及0.5ms步长的8种输入均在首次向外触边终止，终点样本和事件时刻一致。第二组输入在半步及整步末都已返回轨道内，防止仅增加一次半步抽查。
2. 合法整步时长：0.043s输入在修复前抛出容量错误；修复后0.043s、1.001s、1.002s在两种步长下完整运行。非整步、非有限、零/负时长，以及物理步/样本容量越界仍被拒绝。
3. 实际构建身份：在旧应用的真实Chrome导出中断言64位源码摘要，得到空字符串而失败。修复后实际下载的配置同时匹配dist/build-info.json、当前Git来源和构建输入摘要；两个原始导出及本报告元数据携带同一个身份。原生Node单元会话明确标记为未打包，不能冒称同一浏览器构建。

完整检查使用现有npm run check；35项测试中包含14项会话测试，类型检查和生产构建通过。原有浏览器交互、后台暂停、错误文件拒绝、下载读回、10秒1001点静止平衡及两种桌面宽度继续验证。具体环境、身份、实验UUID及原始文件摘要见[verification.json](verification.json)。

[source_sha256](verification.json)覆盖实际构建源码，source_revision记录构建时Git HEAD，source_dirty=true如实表示该构建发生在提交前；不是声称旧HEAD已经包含本轮修复。提交后的相同构建输入具有相同源码摘要。旧版本的原始证据留在上级目录，不重写历史。

新增数值事件定位方法、时长容差及构建字段定义见[实现契约](../../../design/t01-implementation.md)。回归通过不代表完整物理P0、控制可达性或工作区可靠性通过。
