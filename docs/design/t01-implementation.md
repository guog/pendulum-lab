# T01：最小独立物理实验的实现与记录契约

本实现对应[任务 #6](https://github.com/guog/pendulum-lab/issues/6)、[QV-1](https://github.com/guog/pendulum-lab/issues/4)及已确认的to-spec测试接口。用户本轮调用implement授权实施这个切片；不把此前“仅确认需求”的记录当成此后开发的阻断条件，也不由此展开其余11项任务、合并或软件发布。

## 实现范围与选择

使用TypeScript、原生DOM/CSS及Vite。应用没有运行时框架依赖，构建产物是静态页面和浏览器Worker。开发及预览服务器只服务静态资源，不计算物理或提供本地文件服务。

实验会话是页面与测试共用的主要接口。配置、时间标记命令、状态、样本、事件、结果和导出都经过该接口；物理积分在Worker执行。Node直接运行可擦除类型的TypeScript测试，另用TypeScript编译器做类型检查；浏览器验证使用独立命名会话中的真实已安装Chrome。

目前只有自由运动。执行器请求力和实际力均为0；记录其候选能力参数不表示执行器限制、自动起摆或控制验收已经完成。目录持续记录、工作区互斥、备份迁移均不在此切片。

## 基准输入

简单及标准的质量、杆长、配重位置和轨道沿用QV-1。两种公开基准都显式将库仑摩擦、滑块粘性及关节粘性覆盖为0，覆盖项和实际完整参数随配置保存，不静默更改预设用于正式控制的值。

- 零阻力释放：摆角为+π/2rad，车位为0，两速度为0，观察窗口10s。该明示水平初态用于直观看重力运动，不替代标准自动起摆的+πrad初态。
- 静止下垂平衡：摆角为+πrad，车位及两速度均为0，窗口10s，不添加初扰。

默认步长1ms、控制周期元信息10ms（本切片没有活动控制器）、采样10ms；会话也接受0.5ms数值基准步及已批准的1ms/100ms采样，以整数物理步计数，拒绝不可整步推进。内存记录有实现容量限制：最多600000物理步、100001个样本；当前页面固定10s，不提供长时或无限运行。

## 方程、质量分布与数值方法

x向右、y向上，θ从向上竖直开始逆时针为正，杆上距轴r的点坐标为(x−r sinθ, r cosθ)。设车质量M、杆质量m、点质量配重p、杆长L、配重位置r：

- 总平动质量S=M+m+p；一阶质量矩A=mL/2+pr；绕轴惯量B=mL²/3+pr²。
- 动能为S v²/2−A cosθ·vω+Bω²/2，势能为Ag(1+cosθ)，下垂势能零。
- 联立S·x''−A cosθ·θ''=F−A sinθ·ω²，以及−A cosθ·x''+B·θ''=τ+Ag sinθ。
- 当前F仅含滑块阻力，τ仅含关节阻力。库仑平滑采用tanh(v/vs)，vs=0.01m/s并随配置显式记录；粘性阻力依配置计算。

采用固定步经典RK4，同时积分阻力耗散做功；能量残差为当前机械能加累计耗散减初始机械能。这里是实现方法，不是30秒能量漂移或全部数值P0已经通过的声明。

恰为整数π的指定静止平衡输入保留精确零重力矩，避免Math.PI表示误差制造隐藏初扰；不对一般角度或速度进行阈值吸附。模型版本rigid-cartpole-rk4-2使用RK4四阶段导数构造三次步内连续插值，先求滑块位置插值的全部内部驻点，按时间分成单调区间，再在第一个触边区间内二分40次定位终止点。这样能发现步内越界后返回、步末仍在轨道内的情况。终止状态和耗散量取同一连续插值，完整无事件物理步仍使用原RK4结果；记录实际终止时刻，不截断位置或反弹。这里定位的是数值插值轨迹的首次触边，不宣称已证明真实连续系统的全部误差界。非有限数值冻结在最后有效状态，不能生成NaN/Infinity样本。

## 会话、时钟与异常

状态为ready、running、paused、completed、stopped、error。仅ready能开始；暂停可继续；停止或窗口完成后必须重置。重置产生新实验身份，不沿用旧记录。配置在创建时复制，读出的快照也复制，调用者不能回写实际实验。

采样点与渲染刷新分开；开始点和真实终止点可额外采样，同一时刻不重复。后台暂停在消息处理边界生效并记录reason，返回页面不自动继续。Worker每次推进16ms仿真时间，之后让出执行环境，不按现实延迟补算或丢步。实际运行倍率与物理时间分别显示。

参数校验拒绝越界、非有限值、非法组合、不可整步时长和超容量记录，不自动截断。创建与推进均先取整步数，再以1e-12s容差核对时长，避免0.043s、1.001s等合法整步输入受浮点除法误差影响；容量以整数物理步/采样步计算，不改变600000物理步和100001样本上限。计算异常、触边、用户终止、正常窗口完成分别记录；Worker加载或运行环境失败时界面冻结操作并给出恢复提示。

## 研究导出包与schema 1

导出为UTF-8、LF换行的JSON研究证据包。它承载逻辑文件内容，不创建或冒称正式工作区目录；与后续工作区分块提交协议分别管理。

| 外层字段        | 类型与语义                                    |
| --------------- | --------------------------------------------- |
| schema_version  | 整数1                                         |
| kind            | 固定pendulum-research-bundle                  |
| experiment_id   | 本次实验UUID                                  |
| prepared_at_utc | 导出包准备时刻的UTC字符串，不是落盘已确认时刻 |
| files           | 相对逻辑名称到UTF-8文本内容的映射             |

包中包含完整配置、一个原始CSV块、一个JSONL事件段、结果及清单。CSV列沿用QV-1已确认顺序，数值使用可回读的原精度十进制表达；累计角保留，规范化角范围为[-π,π)。执行器、水平外力和关节力矩做功分别有列，当前自由运动三者均为0。阻力耗散和能量残差独立记录。

配置包括schema版本、工况及版本、基准说明、实际物理参数、显式覆盖项、初态、步长/周期/窗口、模型/应用/控制器/规则版本和浏览器上报环境。样本及事件按递增序号和仿真时间记录；同刻事件可用序号消歧，样本时间严格递增。触边事件独立携带四状态、轨道边界及违规条件；每次证据包请求记录export事件，stage=requested且persistence_confirmed=false，不冒称文件已保存。

结果关联同一实验身份及规则版本，包含运行状态、最后状态、记录点数和限制。正式控制资格固定not_eligible，首次稳定、耐久和两扰动均为not_executed。暂停导出保留当前状态，但不捏造未到采样时刻的周期样本；清单说明最后实际采样时刻。

清单列出配置、原始CSV、事件和结果的字节长度及SHA-256；清单本身不对自身生成递归摘要。清单不标记工作区已提交或已封存。摘要用于内容校验，不是身份认证，也不抵抗拥有完整重写权限者同时改写清单。

## 实际构建身份

配置新增versions.build（源码SHA-256或null）和build_identity（身份对象或null）。身份对象包含source_revision（实际Git HEAD或null）、source_sha256、source_dirty（应用构建输入相对HEAD是否改变，或在Git不可用时为null）。应用语义版本继续单独保留，不能用固定的0.0.0+t01替代源码身份。

Vite为页面/Worker提供构建时身份，并输出同一dist/build-info.json。摘要输入为src/全部普通文件，以及index.html、package.json、package-lock.json、tsconfig.json、vite.config.ts和scripts/build-identity.ts。相对路径排序后，每个文件按JSON.stringify([路径,字节长度])加LF、再加原始文件字节串联，计算SHA-256；来源文档、原始资料、测试证据和Git元数据不进入该源码摘要。构建期间输入变化会使构建失败；身份为源码/构建来源说明，不是二进制签名或安全认证。

Git修改状态检查整个src/及固定构建输入，包含尚未暂存和已暂存的源码删除；不能只检查当前仍存在的文件。删除会改变源码摘要并标记source_dirty=true，恢复原输入后返回原摘要和干净状态。对应回归在隔离Git源码副本中执行真实生产构建、读取dist/build-info.json，不修改用户工作区。

生产静态应用在Worker加载时取得身份，完整配置随后冻结。开发源文件变化会使开发模块缓存失效并重新加载页面，避免继续使用旧身份；内存实验仍须事先导出。直接用原生Node运行会话而没有经过Vite时，两字段明确为null，不伪装成已验证浏览器构建。无Git的源码归档仍可构建并记录源码摘要，Git字段为null。

实际Chrome回归在下载的证据中校验源码摘要格式、Git来源，并核对其与静态构建清单及当前输入的身份一致；验证报告保存同一个build_identity。

## 保存确认语义

- “生成下载副本”只准备文件；点击下载只表示下载已发起，均不标“已确认导出”。
- Chrome保存对话框路径在用户点击时先请求目标，再准备证据，写入并关闭后读回实际文件，比较SHA-256后才确认导出。
- 下载后也可由用户选取实际磁盘文件，读回并与当前导出包摘要比较后确认。文件不一致、取消或写入失败不产生成功状态；校验上限64MiB。
- 实验继续、重置或配置改变后旧文件仍可作为旧快照证据，但不能表示当前记录已导出。未确认数据在刷新或关闭时会丢失，界面与离开提示均说明这一点。
