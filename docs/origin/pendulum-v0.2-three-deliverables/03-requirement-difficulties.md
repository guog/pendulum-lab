# 一阶倒立摆项目：关键需求难点与验收风险分析

**版本** V0.2；关联 ADR-001～ADR-190。  
**关注范围** 用户真正需要什么、目标是否同时成立、验证/验收口径如何明确、虚拟实验与现实设备关系、数据资产可信性等。刻意不把前端框架、Worker、目录 API、算法库的编码难度当成需求本身的难点。  
**现状** 所有候选物理参数、性能与验收阈值均未经实测数值仿真验证；本文不声称任何 P0 已通过。

## 结论先行：最难的不是“画出一个倒立摆”，而是证明客户想要的结果真实、可达、可重复、可解释

项目实际包含三个相互独立、必须分别通过的命题：

1. **物理可信**：方程真实反映已约定的简化装置，速度、受力、摩擦、惯量、能量收支一致；不是逼真的动画。
2. **控制可达**：在有限轨道、最大驱动力、速度、功率和给定质心/质量下，从精确静止下垂确实能快速起摆并回到中心稳定；没有暗中修改条件。
3. **实验可信**：用户可以明确重复、比较、保存、恢复，正式结果必须与冻结参数、版本及真实记录一一对应；不是“偶然成功的一次演示”。

这三者不能互相替代。数值求解正确不证明可控；可控不证明某组客户参数或真实设备可用；漂亮 PDF 也不证明数据来源可靠。

## 1. 排名前七的“用户需求本身”关键难点

### D-01 · “快速立起来”可能在给定装置上物理不可达（最高优先级）

**客户要什么**：自然下垂→自动起摆→连续5秒四指标稳定，简单≤30秒、标准≤60秒，随后20秒持续稳摆，可受扰恢复。

**为什么是需求难点**：力、机械功率、最大速度和有限轨道互相制约；杆越重、质心越远、轨道越短可能越难。更强的驱动力也不必然使控制更快，因为必须避免碰到导轨边界并将车回到中心。标准工况控制器增益没有实际整定，不能事先承诺可达。

**需求裁决**：简单、标准是强制验收；困难是探索性场景。原始物理参数与验收标准均锁定为**候选**，以后验证失败必须保留原数据并按 ADR-065/161 新增受控决策。不能自动增加轨道长度、推力或放宽时间。

**应取得的证据**：完整轨迹、能量曲线、控制器请求力/实际力、饱和与超速、导轨位置、首次稳定时刻、额外耐久、失败原因。只展示动画不算。

### D-02 · “自然下垂”和“自动起摆”在数学上有一个特殊零输入陷阱（最高优先级）

**客户要什么**：摆杆初始角恰好 +π rad、车位于中心、所有速度零，不经用户推一下，自动起摆（ADR-109、172）。

**需求难点**：某些纯能量反馈控制律在完全静止的自然下垂平衡点可能输出零力而永远不动；如果通过随机初扰或暗改角度，虽能“动起来”却没有满足客户要求。

**需求裁决**：必须通过明确的、确定性的主动启动控制力起摆，并纳入正式验收。虚拟试验可提供其他初态，但绝不能用其替代标准初态。

**证据**：首个非零控制力及其方向、产生时间、起摆过程和完全不变的四项初态记录。

### D-03 · “立起来”不是单个角度指标，标准互相约束（最高优先级）

**客户要什么**：不仅杆朝上，还要角速度小、车近轨道中心、车自身速度小，并保持足够久。

**已明确的候选阈值**：摆角误差≤3°、摆角速度≤0.2rad/s、车位置偏差≤0.10m、车速度≤0.10m/s，四项同时满足持续5秒；首次成功后20秒耐久持续满足。失稳后10秒内包含完整5秒恢复。

**需求难点**：达到某一时刻竖直、在运动中穿越竖直、车在中心但仍高速行驶、短暂满足阈值、长时间稳住是不同结果。验收时还要区分“抑扰成功”与“失稳后恢复成功”。

**证据**：以仿真时间为统一口径，四维同时达标窗口、20秒完整耐久区间、事件与恢复期间的实测状态，不允许只用瞬时截图判定。

### D-04 · 可调质心改变的是整个被控对象，不只是动画中的配重位置（高优先级）

**客户要什么**：通过改变配重质量和位置，观察不同质心/惯量对自然运动和起摆控制难度的影响。

**需求难点**：更换配重时重力矩、质心及转动惯量同时变化；模型必须有杆自身的分布质量，而不是无质量杆加一个末端重物。不同参数组合也不保证同一个控制器参数一定稳定。

**已决定**：均匀有质量细刚性杆＋可移动点质量配重；一旦改变杆长/质量/配重等物理结构参数，必须重新初始化实验并生成新快照。不同控制器参数由验证阶段整定。

**证据**：物理参数、计算得到的质心和惯量、配重变化前后对比、动能/势能及控制所需力。不要把未知惯量当常量。

### D-05 · 客户说的“舵机力量/功率”不是单一数字（高优先级）

**客户要什么**：限制执行机构的运动能力，研究不同电机能力对稳定控制的影响。

**需求难点**：力上限 N、速度上限 m/s、功率上限 W 是三种不同约束。静止时机械功率为零但可施加有限大推力；制动可能受功率限制；外力可以将车推到超速。直接截断车速度会让仿真不真实。

**已决定**：记录请求力、实际力与限制原因；外力和摩擦单独进入方程；不得篡改被控对象的连续物理状态。正式验收如果发生未经许可的超速即不通过。

**证据**：力/速/功率曲线，饱和时刻与持续时间；校验能量收支，并能解释“是算法没有找到控制，还是执行器根本推不动”。

### D-06 · “更真实”存在有意简化与真实设备之间的鸿沟（高优先级）

**客户要什么**：先在虚拟空间验证，再考虑复杂二阶摆与可能的实际装置。

**需求难点**：客户语言中“真实”可能指三种层次：具有合理重力和惯量；与某台演示硬件参数吻合；可直接转移到实物控制。当前基线只承诺**第一层**，并没有真实摩擦标定、传感器误差、接触碰撞、电机传动或控制延迟。

**已决定**：二维无杆/轨碰撞模型，简化力-速-功率执行器，理想状态反馈，摩擦平滑近似。明确界面和 PDF 标注模型范围，仿真成功不等于实物已通过安全/控制认证。

**需求动作**：验收时先演示“在约定模型下正确”，不要将未来可能的硬件校准作为首版隐含义务。

### D-07 · “所有实验文件在我的目录里”是用户对数据所有权的要求（高优先级）

**客户要什么**：每次浏览器主动打开本地工作目录；配置、轨迹、事件、图表、诊断、PDF 和过程产物均能在目录下找到；不用浏览器内置实验数据库。

**需求难点**：用户要的是**可携带、可检查、可恢复、可追溯的数据资产**，不仅是另一种技术存储方式。要定义“完整”是否包含中断实验、临时文件、历史版本、重新生成的报告和索引。还要处理同一目录只能有一个实例打开的强约束。

**已决定**：分块 CSV、JSONL、不可变实验快照、校验清单、原始封存、可重建索引、备份恢复；第二实例连只读也拒绝。跨浏览器/跨来源真正目录独占尚未获得技术证据，是 P0 阻断风险。

**证据**：复制整个目录后，独立恢复有效实验；故障时能明确说明最后已保存的样本；不会假称历史完整；严格拒绝同时打开同一目录的第二实例。

### D-07a · “设置角度后自然掉下来”也存在精确平衡点例外（高优先级）

**客户要什么**：设置一个初始摆角，松开后摆杆受重力自由运动。

**易误解点**：如果摆杆恰好竖直向上（0 rad）、角速度严格为零、滑块不动，完全理想的确定性动力学会保持这个不稳定平衡点，**不会凭空自己倒下**；这不是计算错误。自然下垂（+π rad）、初速度零同样是静力平衡点，不加力不会自行起摆。

**需求边界**：自由运动模式忠实于指定初态和受力；如客户想演示“轻轻一碰就倒”，应使用明显标注、可复现的初始偏角或外部扰动，不能暗中引入隐藏噪声。自动控制模式则按 ADR-109 明确要求从精确下垂位置由控制器主动起摆，两种情况不能混同。

## 2. 重要但次一级的需求治理难点

### D-08 · 标准试验与探索试验必须区分

用户可更改摩擦、配重、控制器增益、扰动幅度与验收阈值，探索实验成功不等于软件正式验收通过。只有冻结工况/控制器/规则/初始条件且无中途调参，才能成为正式证据（ADR-141）。不同版本的历史成绩不能被更新后的算法重写。

### D-09 · 失败要有价值，而不是一个“失败”按钮

应区分：起摆没有足够能量、轨道触边、超速、执行器饱和、无法建立稳态、耐久失败、扰动测试前提阻塞、控制器异常、数值发散、数据持久化失败。每类对应不同的后续动作，不能全部用“控制算法失败”概括。

### D-10 · 多工况比较需要冻结比较基准

简单、标准、困难三档不是标签，需要有完整质量、轨道、摩擦、执行器、控制器和规则快照。不同物理难度的起摆时间和成功率不能脱离其对应版本直接横向比较。标准与困难的失败性质不同，困难允许探索性失败。

### D-11 · 数据长期可信比一次文件导出更复杂

原始记录、事件、结果和报告必须来自同一实验快照。显示降采样不能改写原样本，异常峰值不能被画图采样掩盖。已提交数据与崩溃中临时文件必须区分；损坏应保留证据、不能插值伪造；迁移要保留原始副本。

### D-12 · “二阶以后再做”仍需界定扩展责任

首版要预留关节数量、状态/控制契约的扩展能力，但不需要通用多体求解器。否则会同时承担一阶控制可达性和通用多体架构两类难题，使首次交付偏离客户的“小测试”初衷。扩展接口可以验收，但不得将二阶动态/算法纳入首版强制要求。

## 3. 最容易产生误解的需求口径（简明消歧）

- **“360°旋转”**：允许连续多圈并保留累计角，不代表真实杆必须能穿透真实轨道；首版碰撞是有意忽略。
- **“初始角度 180°”**：明确选 +π rad 而非随机选 ±π，确保输入一致。
- **“快速”**：从自动启动到完成连续5秒稳定计算，采用仿真物理时间；并非首次达到竖直的那一瞬间。
- **“恢复”**：若始终未离开稳定区，记抑扰；离开则在10秒内完成5秒新稳定期。
- **“保持稳定”**：四项阈值均持续成立，不是只有摆角近零。
- **“执行器 40W”**：机械输出功率候选值，不是电机电输入功率，更不是永远可以输出20N且速度任意。
- **“所有数据”**：所选采样周期下的全部原始样本、事件和所有过程产物；不是强制落盘每一次物理积分，也不是只保留最终 PDF。
- **“一键打开文件夹”**：每次经浏览器用户授权选择目录；不能假定权限永远保留或可以无交互读取用户磁盘。
- **“只读”**：仅当目录空闲但写权限不足时可读；若已被其他实例占用，ADR-182 要求连只读打开都拒绝。
- **“需求确认”**：表示目标被确定，不表示模型可达、代码已实现或验收已经通过。

## 4. 风险按阶段验证，而非一次性承诺

### Gate 0 — 用户需求完整性

**输入**：190项 ADR、SRS、目录文件契约、风险清单与测试矩阵。  
**判断**：是否有相互冲突的现行要求？是否保留修订链？哪些详细字段/事件顺序仍未定？  
**产出**：可批准的需求基线，而非“已经成功”的技术结论。

### Gate 1 — 物理与目录双 P0 可行性验证

这两个主题均需尽早进行，但可在不同的验证任务里开展，避免互相污染问题定位。

- **文件风险**：目录严格独占（跨 Chrome/Edge、HTTPS/localhost）、崩溃写入与恢复。如果做不到，按 ADR-183 必须提交新 ADR，不允许假成功。
- **物理风险**：能量收支与积分收敛，参数范围和坐标一致性。暂不依赖控制器算法的成败判断物理模型正确性。

### Gate 2 — 控制可达性验证

从完全精确静止下垂起摆，在简单/标准工况达到 5 秒四项稳定，并完成20秒耐久；两扰动分开测。控制器增益由真实实验验证后冻结。**若失败，只能提出有证据的变更方案，不自动降低目标。**

### Gate 3 — 用户价值与最终验收

用户能够清楚看到为何可控/不可控，调整何种参数后结果如何变化，原始数据可独立检查，正式/探索结果边界清晰。完成18次基础测试及独立耐久、文件与报告、浏览器桌面性能验证。

## 5. 针对客户评审最值得展示的五项证据

1. **一次完全静止下垂成功起摆**：第一步由控制器主动施力，轨道不触边，完整时间与控制力曲线齐全。
2. **改变配重位置的对照试验**：相同其他参数下质心、惯量及起摆行为随配重变化，能解释物理原因。
3. **执行器能力限制试验**：展示同算法下最大力/功率降低时的饱和、超速与失败，而非一味调好看。
4. **抑扰与失稳恢复的区别**：一个保持在阈值内，一个退出后重返，报告可客观区分。
5. **故障后恢复完整历史**：发生关闭或损坏后能准确列出已封存样本和缺口，再次打开本地目录不会丢失或伪造历史。

## 6. 不能预设结论的五个开放问题

- 选定简单/标准物理参数在现有驱动上限与轨道长度下是否真实可控？**未验证。**
- 哪种起摆/稳摆控制及参数在不偷偷改变初态时达标？**未整定。**
- 浏览器是否能对相同物理目录实现跨来源、跨浏览器真正单实例独占？**P0 未验证，可能无法同时满足既有纯前端架构。**
- 1ms积分及各项数值容差能否同时成立？**未验证。**
- Chrome/Edge 在冻结的办公硬件上是否能同时绘图、计算和保存高频数据而达到60FPS？**未验证。**

## 7. 给项目负责人和编程 Agent 的最终建议

1. **不要把“需求多”当成“需求已被证明”。** 保留所有190项 ADR，并把风险证据留在对应实验文件目录中。
2. **先验证最可能推翻架构或目标的假设。** 首先是单目录严格独占与文件恢复，其次是动力学正确和有限执行器的起摆可达性。
3. **用户演示不只看杆是否竖直。** 必须让客户看到四项稳定指标、真实限制、异常过程、可调质心对动力学的影响。
4. **正式测试与研究探索分开。** 探索性失败也是有用的工程结果，不应篡改原始数据或自动“调到成功”。
5. **所有新的不可达事实都生成决策，而非修改历史。** 通过证据 → 影响分析 → 受控 ADR → 用户确认 → 更新基线。

**结论**：客户需求真正困难之处是对“现实性、自动起摆、快速稳定、可调对象和可信实验”的同时要求。项目成功的最有价值输出，应是一套在物理边界内能解释成功与失败、可复现和可审计的网页实验系统，而不只是一个看起来能够立起摆杆的动画。
