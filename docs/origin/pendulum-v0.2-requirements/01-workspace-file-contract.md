# 一阶倒立摆仿真系统 — V0.2 工作目录文件契约

- 文档编号：SPEC-WKS-001
- 版本：V0.2 候选详规 / 2026-11-01
- 需求决策：ADR-001～ADR-190，重点 ADR-177～ADR-190
- 状态：需求分析产物，尚待最终基线审查；非程序实现或已验证结果

## 1. 规范性边界

1. 首版桌面 Chrome、Edge，通过 HTTPS 静态站点或 localhost 静态服务运行；用户**每次使用均主动选择并授权**本地目录（ADR-177～179）。目录外不读写个人数据；静态应用缓存不作为实验持久化仓库。
2. 用户目录是**全部**物理配置、实验原始数据、事件、诊断、图表、PDF、验证证据和过程产物的唯一持久化来源。不得将 IndexedDB、OPFS 作为实验记录或持久化索引（ADR-177、188）。
3. 同一物理工作目录同一时刻只允许一个应用实例打开，包括读操作；第二个实例拒绝打开（ADR-182）。这一目标尚无经过验证的跨浏览器、跨来源实现，属于 P0 阻断风险（ADR-183）。不得以同源 Web Locks 或单文件写入锁代替其验收证明。
4. 无写入权限但可读时可进入只读模式；不能启动要求完整记录的新实验（ADR-180、167）。但若目录已经被其他实例占用，则即使只读也应**拒绝打开**（ADR-182 优先）。
5. 完整性校验散列只能发现意外或人为修改，不能提供用户身份认证或抵抗有意重写内容的数字签名；首版不声称实现来源认证（ADR-146、189）。

## 2. 目录布局（字段与路径命名为建议详规，待最终基线批准）

```text
pendulum-workspace/
├── workspace.json                  # 工作区格式、身份、版本和索引修订
├── presets/                        # 公共基准与简单/标准/困难工况及自定义工况
├── experiments/
│   └── <experiment-id>/
│       ├── manifest.json           # 权威元数据、版本、已提交分块与封存状态
│       ├── config.json             # 创建实验时的完整不可变快照
│       ├── samples/                # chunk-000001.csv 等，已提交分块不可变
│       ├── events/                 # part-000001.jsonl 等，事件 JSONL 分段
│       ├── result.json             # 首次稳定、耐久、扰动等分类结果
│       ├── charts/                 # 衍生图表，附生成版本
│       ├── reports/                # 衍生 PDF，附生成版本
│       └── diagnostics/            # 计算错误、存储异常与检查结果
├── index/                          # 可重新生成的历史索引/摘要
├── validation/                     # 数值、控制、浏览器验收证据
├── backups/                        # 用户明确操作创建的备份
└── tmp/                            # 未提交临时产物；不得当作已提交数据
```

事件路径采用 JSONL **分段**以匹配分块持久化要求；若最终选择单个 `events.jsonl`，仍必须满足 ADR-186、168 的安全提交及中断恢复要求。目录名称与切块大小不构成已确认 ADR 的新增事实。

## 3. 文件格式与必须表达的语义

### 3.1 `workspace.json`

- 必需语义：`schema_version`、不随路径变动而变化的 `workspace_id`、创建时间、工作区状态、当前索引版本、应用版本兼容范围。
- 工作区身份用于显示和完整性关联；不得把路径字符串或浏览器 origin 直接视为唯一物理身份。
- 已有且有效则打开；空目录允许初始化；非空但无有效工作区标识时拒绝自动初始化，不移动、不删除无关文件（ADR-184）。
- 工作区清单与历史索引不同：`index/` 全部可根据实验清单重建（ADR-188）。

### 3.2 `config.json`

- 原始工况/公共基准/工况覆盖项及展开后的**完整快照**；后续编辑原工况不影响已创建实验（ADR-064、132）。
- 必需元信息：物理模型版本、控制器标识及版本、参数快照版本、验收规则版本、完整初始状态、物理积分步长、控制周期、采样周期、扰动配置、起摆/耐久/恢复时限、浏览器和运行环境标识。
- 统一 SI 单位及坐标：x 向右、y 向上、摆角从竖直向上逆时针为正、标准下垂 +π rad（ADR-148、172）。
- 标准起摆的四个初始条件：滑块位置 0、滑块速度 0、摆杆连续角 +π rad、角速度 0。
- 固定标准工况与探索实验的区别，禁止中途调参实验取得固定参数正式验收资格（ADR-116、141）。

### 3.3 `samples/chunk-*.csv`

- UTF-8，首行列名；十进制数使用点号，小数精度不得因为显示格式导致丢失；NaN/Infinity 不能作为合法物理状态样本（ADR-035、069、185）。
- 必需字段语义（建议字段名待审查）：
  - `sample_index`：严格递增的整数采样序号；
  - `sim_time_s`：仿真物理时间（秒），不是墙钟时间；
  - `cart_x_m`、`cart_v_m_s`；
  - `theta_unwrapped_rad`、`theta_wrapped_rad`、`theta_dot_rad_s`；
  - `force_requested_N`、`force_actual_N`、`force_external_N`、`torque_external_Nm`；
  - `control_mode`、`controller_phase`；
  - 动能、重力势能、执行机构机械功率、外力做功及耗散等可扩展列，具体字段随版本化 schema 明确（ADR-073、088、121、128）。
- 实验采样周期与绘图采样率分离。完整历史指**所有已规定采样周期的原始样本与事件**，不是每一物理积分步强制落盘（ADR-097、102、140、169）。
- 每个已提交分块拥有唯一 `chunk_id`、第一/最后序号、时间范围、样本数、字节长度、散列校验；同实验内分块不交叠、无未说明的缺口。

### 3.4 `events/part-*.jsonl`

- UTF-8，每行独立的结构化事件，不运行文件内脚本；行级格式有版本及事件类型。
- 必需语义：事件序号、仿真时间、事件类型、事件载荷、控制器/模型版本关联、事件生效时刻。
- 至少覆盖：开始、暂停/恢复、模式交接、控制器参数变化、扰动起止、限幅/饱和、超速、安全区、边界触碰、首次稳摆、耐久失败或完成、抑扰成功、失稳恢复、错误冻结、数据保存异常。
- 同时刻事件按固定可复现顺序处理（ADR-138）；**确切的事件优先级顺序属于详细计算契约待审查项**，不能擅自认为已批准。

### 3.5 `manifest.json`

- 唯一权威实验元数据；标识 `experiment_id`、创建时间、运行状态、模型/控制器/工况/验收版本、采样规格、当前清单修订、已提交 chunk/事件文件列表及其校验、已持久化最大仿真时间、数据完整性标记、结果引用、封存信息。
- 建议状态：`created` → `running` → `interrupted` / `failed` / `completed` / `invalid`；`sealed` 表示完成数据一致性核验后的封存属性，而非控制成功。
- 不允许因 `result.json` 记录了“首次成功”就将未完整记录实验标记为正式验收通过（ADR-113、119、141、149、168）。
- 已提交分块及对应事件的**清单引用**必须最后发布；文件创建、写流关闭、完整性校验与发布是不同动作。浏览器文件 API 不提供多文件统一事务，必须实际测试异常断电/关闭时的表现。

### 3.6 `result.json` 与衍生报告

- 分别记录首次达到连续 5 秒的四维稳定判据、额外 20 秒稳摆耐久、每种扰动的“抑扰成功/失稳恢复成功/失败/阻塞”、超速与触边及异常、正式验收资格和应用的规则版本（ADR-173～176、119、131、141）。
- `result.json` 作为本次验收结果关联其原始样本/事件和配置快照；结果历史不因软件升级覆盖（ADR-170）。
- PDF/图表后续重新生成时建立衍生版本和来源记录，不回写封存原始数据（ADR-098、189）。

## 4. 持久化与恢复的规范性流程（行为契约，非代码）

1. 在合法授权和确认独占后读取并校验工作区身份/版本；没有有效独占不得打开任何历史实验（ADR-182～184）。
2. 创建唯一实验目录和不可变配置；写入初始清单；数据完整性要求不满足则不得开始（ADR-167）。
3. 将样本及事件以有界批次写入未提交文件，关闭并校验，再发布清单中对完整文件的引用；清单未引用的文件属于待排查孤儿文件，不视为有效原始记录（ADR-168、186）。
4. 异常退出时保留所有已确认提交的分块；下次打开标记中断，显式展示最后提交时间和缺口，不自动补造数据（ADR-113、149、187）。
5. 正常结束后校验时间序列与事件关联、文件清单与结果一致性，才允许封存（ADR-168、189）。
6. 索引可删除后重建，不得因此删改实验清单及数据块（ADR-188）。
7. 工作区升级必须先保留可恢复原始版本，在新版本全部验证后切换；失败不得留下半迁移且不能覆盖唯一有效副本（ADR-115、190）。

## 5. 数据权限与安全

- 任何输入导入仅视为数据，限制大小、数值/格式/引用关系及版本，拒绝执行脚本（ADR-142）。
- 默认本地私有，不自动上传实验数据；互联网仅用于明确的应用资源加载/更新（ADR-143）。
- 无读写权限时只读；目录已被其它实例占用时直接拒绝打开而不是降级（ADR-180、182）。
- 不假设浏览器刷新后持续保留授权，用户每次通过显式操作选择目录（ADR-177）。

## 6. 必须保持“待验证”的条款

- P0：同一物理目录跨 Chrome/Edge、HTTPS/localhost 的严格单实例独占（ADR-182、183）；不能仅凭 Web Locks 同源互斥或单文件 exclusive 写流推论成功。
- P0：分块已提交清单在突然关闭、写入失败及跨文件更新期间的完整性；单文件完成写入与跨文件原子提交不同。
- P0：在真实浏览器/磁盘条件下的数据规模、权限撤回、只读状态、容量耗尽和恢复。
- 需决定的详规：字段正式英文名、文件名及路径版本、分块大小/提交周期、同一时间戳事件处理优先级、备份恢复时的完整校验字段、磁盘读写冲突判定与恢复条件。

## 7. 外部 API 依据（只作可行性说明，不代替测试）

- MDN `showDirectoryPicker()`：安全上下文、用户激活及读写授权要求。
  https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker
- MDN `Web Locks API`：锁作用域限于相同 origin。
  https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API
- MDN `createWritable()`：独占选项针对单文件写流，通常关闭后将变更反映到目标文件。
  https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable
