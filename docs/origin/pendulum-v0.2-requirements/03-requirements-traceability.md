- 追踪需求组数量：38。

- 每项 ADR 后续需进一步拆为正式 SRS 条款及单项测试场景，并补入证据位置、实际结论、执行版本及验证负责人。

## 3. 状态解释

- 需求已确认：仅说明用户已选择，**不**说明实现和验收已通过。
- 待验证：已有检查规则但没有真实执行证据。
- 阻断：不满足则无法声明相应技术/正式发布基线通过，例如跨浏览器跨来源独占。
- 已延期：移动端，ADR-178 的适用范围优先。

## 4. 必须重点审计的修订链

- 数据载体：ADR-080、096、102、103、113～115、125、144～146、167～170 → ADR-177、180～190。保留完整历史和版本来源。
- 浏览器/移动：ADR-081、083～084、106～107、110、123～124、175 → ADR-178、179；桌面性能仍为候选。
- 多实例：ADR-144 原允许多窗口查看历史 → ADR-182 的全工作区单实例独占；ADR-183 规定无法证明时必须阻断并受控变更。
- 稳定判据：ADR-048 → ADR-173 新增滑块速度阈值；ADR-136 的20秒稳摆同样应用。
- 扰动结论：ADR-050、135 → ADR-174 区分抑扰/失稳恢复。
- 控制器：ADR-008、027、158 要求整定和参数冻结；未验证前不可认定可控。

## 5. 追踪矩阵完成标准

1. 对 190 项 ADR 逐条核实当前有效版本、显式修订来源、对应 SRS 条款及至少一个验证路径。
2. 对强制发布要求提供明确测试输入、方法、可观察判定和数据证据。
3. 对待验证指标标注“候选/未执行”，不得展示绿色通过结论。
4. 对所有 P0 失败/阻断记录受控 ADR 路径，不能通过暗改门槛消除风险。
5. 最终由用户根据 ADR-151 显式确认需求基线后才允许进入开发。
