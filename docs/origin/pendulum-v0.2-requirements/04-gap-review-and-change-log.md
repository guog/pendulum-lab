# V0.2 最终需求审查 — 未闭合项与修订日志

- 文档编号：REVIEW-BASELINE-001
- 状态：需求审查结论 / 尚未批准开发
- 已确认：ADR-001～ADR-190 共190项。ADR-183=A；ADR-184～190=B。

## 1. 已收敛的结论

- 原始客户诉求（一阶刚体摆、360°自由运动、受限滑块、自动起摆稳定、可移动配重、未来二阶扩展）均有需求映射。
- 首版纯前端桌面 Chrome/Edge，HTTPS 或 localhost 启动，由用户每次授权本地工作目录；目录是实验数据的唯一持久化来源。
- 已明确 CSV 分块、JSONL 事件、不可变快照、严格归档、封存、备份、索引可重建、损坏保留和安全迁移规则。
- ADR-182 严格要求同一物理目录只允许一个实例打开；ADR-183=A 明确：在跨浏览器/跨来源验证失败时阻断对应正式验收并重新决策，不自动改变架构。
- 简单与标准工况需要从 +π rad 精确静止下垂主动起摆，四项阈值连续5秒，独立20秒稳摆与两种扰动；18次基础标准控制运行。

## 2. 尚未闭合的需求详规（不等于要求再增加产品功能）

1. **SPEC-GAP-01 P0**：跨 Chrome/Edge 与 HTTPS/localhost 同一物理目录独占没有可验证的浏览器级保证。须先完成 P0-WKS-02～05；技术失败触发 ADR-183 规定的受控新决策。
2. **SPEC-GAP-02 P0**：跨文件写入事务不能直接假定，需验证 `manifest` 提交过程、文件关闭语义及异常恢复；如果原子提交不可证明，提出受控替代策略。
3. **SPEC-GAP-03 细节待冻结**：工作目录具体命名、文件格式版本号、字段名、CSV/JSONL 切块尺寸与提交频率尚属建议详规；在正式 SRS 签署前需定稿，但不强求先实现代码。
4. **SPEC-GAP-04 细节待冻结**：同一仿真时刻事件处理的严格优先级与采样前/后时点，ADR-138 已要求确定性，具体顺序须写成计算契约。
5. **SPEC-GAP-05 验证阶段**：简单/标准工况在有限力、速度、功率、轨道下是否可达；控制器增益和切换阈值尚未整定（ADR-158）。
6. **SPEC-GAP-06 验证阶段**：1ms/0.5ms 收敛、30秒能量漂移≤0.1%、复现容差以及桌面60FPS未做实际测试。
7. **SPEC-GAP-07 验收准备**：参考物理电脑、操作系统及浏览器版本尚未最后锁定；移动端需求依据ADR-178延期。
8. **SPEC-GAP-08 文档工作**：追踪矩阵仍为需求分组版；最后应逐项校对190个ADR、SRS条款、测试用例及实际证据。

## 3. 当前最重要的风险排序

- **先决 P0-A：** 工作区独占。若失败，不应开始宣称遵守 ADR-182 的正式交付。
- **先决 P0-B：** 分块提交、异常恢复和工作目录数据完整性。
- **先决 P0-C：** 动力学能量和数值收敛。
- **先决 P0-D：** 简单/标准工况控制可达性、完整验收判据及重复性。
- **P1：** 统一运行性能、PDF 与数据快照一致性、备份迁移及 UI 完整性。

## 4. 冻结与授权区别

- 需求基线的正式确认只意味着目标、边界、优先级和验证方法被认可，**不表示技术已通过实验验证**。
- ADR-151 要求用户显式批准完整需求基线后才能开发。用户本轮只批准第21轮 ADR，并未批准正式开发或实施任何验证原型。
- 如果后续真实实验失败，只能报告证据、风险和变更方案，并新增受控 ADR，不能偷偷改参数或降低标准（ADR-065、161、183）。
